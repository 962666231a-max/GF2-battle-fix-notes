## 二、最关键的三个修复（按重要性）

### 1. 黑屏 `-<数字>` —— 回错了消息号

客户端发 `CS_StageStart(10304)` 之后等的是 **`SC_StageStart(10305)`**：

```
message SC_StageStart {
  StageBattle stage = 2;
  StageOther other = 3;
}
```

原来服务端回的是 `SC_StageReady(10316)`（只有一个 timestamp）。客户端拿不到战斗数据，在本地初始化处返回 `-<数字>`（客户端错误码表 `IOJGLBFCNMO.CHIICDKCGPP = <数字>u` 取负），随后 `ReceiveError → ConnectClose`，表现为黑屏。

**实测**：回 10305 且两个字段各给一个**空子消息**（payload `12 00 1A 00`）即可进副本。

> 这个坑困了很久：之前所有「猜 StageReady 字段」的实验都无效，因为消息号本身就错了。

### 2. 部署面板 `0/0`「暂无可选择人形」—— handler 未实现

`CS_StageUsableGuns(10300) → SC_StageUsableGuns(10301)`，字段：

```
uint32 stage_id = 1;
repeated uint32 lineup = 2;              // 角色 id 列表
map<uint32, Gun> lineup_guns = 3;        // 完整角色数据
```

**必须用 `GunEntity.GunId`（配置角色 id）做 key**。用数据库行号 `GunEntity.Id` 会导致全部匹配失败 → lineup 为空 → 客户端退化成「显示全角色」。

### 3. 点「作战开始」转圈 —— handler 未实现

`CS_StageInto(10306) → SC_StageInto(10307)`，结构与 StageStart 相同（`stage` + `other`）。

```
message CS_StageInto {
  map<uint32, uint32> guns = 2;   // ★ key = 出生点 id，value = 角色 id
  StageAssistant assistant = 4;
  repeated uint32 action_sequence = 5;
  uint32 preset_id = 7;
  ...
}
```

原来没实现，客户端收到 `NotImplementedException` 后无限等待（转圈）。

## 三、卡住的地方：己方单位不生成

### 已排除（都有实测证据）

1. `StageBattle` 只填 `formation_id / leader_id / predeployment_complated / need_sync_formation`
   → 敌方能动、我方不出现
2. `camps` 只发玩家一侧（含 `Gun`、`sequence`、`uid=出生点`、坐标字符串）
   → 我方仍不出现（有一次现象：敌方也不动）
3. `auto=false` 强制手动 → 无变化
4. `stage_class`/`battle_type` 枚举（PVE=0 / Dz_Battle_Type_Player=0）→ 无变化
5. `SC_StageStart` 里也带 camps → **敌方不再移动**（严重回归，已回滚）
6. 「把部署写回编队1 + formation_id=1」 → 敌我都不动（回归，已回滚）

### 关键观测

- 战斗**纯客户端模拟**：`SC_StageInto` 之后客户端只发 `10105 Sync` 心跳，
  没有任何回合/操作包；点自己的角色也不会发 `CS_StageOp(10317)`
- `camps` 非空时，客户端似乎把它当作「整个战场的全部队伍」；
  只给玩家一侧会导致敌方无单位（或整体初始化失败）
- 客户端在 `camps` 为空时，会按 `StageConfigData.initial_enemies` 自己生成敌方
  → 这解释了「敌人能动、我方不能」

### 建议原作者优先验证的两条假设

1. **camps 必须双方完整**：玩家 camp（`KGMEBGGOOAM=Player0` + `NFGCFGBGMCA`）
   ＋ 敌方 camp（`KGMEBGGOOAM=敌方阵营` + `FDBLKMOOECN(CFMHGIMNBNN)`）
   敌方数据来自 `StageConfigData.initial_enemies` / `enemy_groups` + `EnemyData`
2. 官方回包里 `JPPLEFEAECH`（上场单位）还需要哪些必填字段：
   目前已知 `JEKFJDDLGOO(Gun)` / `Sequence(24)` / `Uid(25)` / `BuffId(26)`，
   另有 `OGEOEEBNDEP(2)` / `GCAABEBJHFL(3)` / `Type(20)` / `Other(21)` 含义未知

> 若作者手上有官方抓包（pcap），本项目里 `NTRSimulator.PcapParser` 已可直接解析对照：
> 放 `Server\Resources\Packets\*.pcap` 后运行即可打印全部消息。

## 五、踩过的坑（避免重复浪费）

1. **发布错项目**：只发布 GameServer 会留下旧的 `NTRSimulator.SDKServer.dll`（const 被内联）。
   必须发布主机项目 `NTRSimulator\NTRSimulator.csproj`。
2. **`AbResourceVersion` 红线**：改成 15157 会触发 **28.61 GB 重下**；保持 `4.0.5136.13967.27078`。
3. **客户端 Plugins 下的 DLL 不能替换** → 触发「修复式重下」28.61 GB。
   要注入就放**游戏根目录**做 `xinput1_3.dll` 侧载（无需注入、无 UAC、删掉即还原）。
4. **`%llu` / `%f` 在 `wsprintfA/W` 里不可用**：参数错位会把游戏**直接搞崩**（我们踩过）。
5. **`wsprintfW` 中文路径**：`CreateFileA` 走 GBK 会失败，全部改用宽字符 API。
6. **`VirtualQuery` 对映射视图报 32KB**：抓 bundle 要用 `CreateFileMappingW` + `GetFileSizeEx`。
7. **raw 直发不被客户端识别**：必须走正常发送栈（`BasePacket.FromIMessageBytes` +
   `MainMessage` + `seq` 回显 + `ComputeEncryptionByte`），否则客户端当没收到。
8. **客户端自己的日志是 UTF-16**（`LocalCache\Log\log_*.bin_cN`），ASCII 解析会得到乱码；
   `Player.log` 恒写在 `%LOCALAPPDATA%Low\SunBorn\少女前线2：追放\Player.log`。
9. **编队不能超过 6 个**：下发 12 条 → 【编队】整页空白。
10. **`formations.json` 必须是对象**：`{ "1": {...} }`；存成 JSON 字符串会在读回时报
    `Expected an object`。
11. **`StageRecord` 必须对所有 type 应答**：只有 11~14 时客户端静默等待。
12. **单位匹配必须用 `GunId`**（配置 id），不是数据库行号。

## 六、我们尝试过但没走通的路（含工具，作者可复用）

### 6.1 侧载 DLL（`xinput1_3.dll`，源码在 `12_GF2\tools\luahook\`）

在游戏根目录放 DLL，由系统加载（无需注入），实现了：
- `gf2_readhook.c`：hook `ReadFile` / `MapViewOfFile` / `CreateFileMappingW` / `CreateFileW`，
  抓**解密后**的资源包（成功抓到 1064 个解密 bundle）
- `gf2_memfind.c`：进程内 UTF-8/UTF-16 字符串搜索（带自身栈/模块过滤）
- `gf2_memsnap.c`：**全量内存快照**（2.79 GB，2949 个区，`memsnap.bin` + 索引）
- `gf2_imgdump.c`：扫描 `BSJB` 回溯 PE 头，dump 已加载托管镜像
- `gf2_aesbp.c`：AES-NI 断点（实测 0 命中 → 资源不是 AES 解密）

触发方式：写 `<out>\_memsnap_now.txt` 这类文件，DLL 轮询检测。

### 6.2 客户端程序集（为什么难反编译）

- `Assembly-CSharp.dll.bytes`（24.79 MB）：**元数据明文、方法体加密**
  （一个 7 字节 `.ctor` 解出来是 `bne.un.s/brfalse.s` 这种非法序列）
- 商业壳标记全无（.NET Reactor / ConfuserEx / Babel / Eazfuscator / SmartAssembly /
  Agile.NET / Dotfuscator / Themida / VMProtect / KoiVM / ILProtector / UPX 都没有）
- `de4dot-cex v4.0.0` 只报 `Detected Unknown Obfuscator`，清洗直接抛异常
- 另有 `Assembly-CSharp.dll.bytes_HUDll.u`（148.75 MB，头部不是 MZ）——很可能是
  **整文件加密的热更程序集**，真码可能在里面
- 结论：自研/去标识化保护器，静态脱壳成本高；**若作者能拿到明文程序集或抓包，一切好办**
